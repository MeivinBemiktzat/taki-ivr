# טאקי טלפוני — גרסת פיתוח ראשונית

Node.js / Vercel / Yemot `type=api` / Hugging Face Storage Buckets.

## חשוב
הפרויקט בשלב **שלד פיתוח** ולא נבדק מול שיחה חיה בימות המשיח. נדרשת השלמת רצף `read` / `api_answer` והעברת מצב בין בקשות לפני שימוש אמיתי. אין לפרסם כמשחק פעיל לפני בדיקות.

## הגדרת Vercel
הגדר משתני סביבה (אותם שמות כמו במונופול):
- `HF_NAMESPACE`
- `HF_BUCKET`
- `HF_S3_ACCESS_KEY_ID`
- `HF_S3_SECRET_ACCESS_KEY`

מומלץ Bucket ייעודי. כל המפתחות מבודדים תחת `taki/`.

נקודת כניסה: `/api/ivr`.

## יכולות במנוע
- חדרים בני 4 ספרות, 2–6 משתתפים, בוטים או בני אדם
- חלוקת 8 קלפים, חפיסה, שליפה, ערבוב ערימת זרוקים
- צבעים, מספרים, עצור, פלוס, שנה כיוון, פלוס 2, טאקי, סופר טאקי ושנה צבע
- הקראת יד מלאה או קלפים חוקיים
- מניעת דריסת שמירה מקבילה באמצעות ETag / conditional writes
- ללא מגבלת זמן לתור

## נדרש להשלמה
- התאמת תחביר קלט `read` והמשכיות שיחה לפי תיעוד ימות העדכני.
- טיפול מלא בהנחת קלף וקליטת בחירת צבע במספר בקשות, כולל הגנה משידור כפול.
- בדיקות יחידה ואינטגרציה לכל חוקי טאקי, לרבות טאקי פתוח ופלוס 2 מצטבר.
- קביעת וריאנט חוקי טאקי מוסכם למשחק.
- בדיקות שיחה חיות ורק אז פריסה לציבור.

הקוד אינו דורש מפתחות API של בינה מלאכותית.

## בדיקה במערכת פרטית — רק לאחר אישור בדיקות

1. פתח פרויקט חדש ב־Vercel מתוך הריפו הזה. אל תחבר עדיין את השלוחה הציבורית.
2. הגדר את ארבעת משתני הסביבה של Hugging Face Storage Buckets המופיעים למעלה. אין לשתף את הערכים שלהם בצ'אט או להעלות אותם ל־GitHub.
3. אחרי פריסה מוצלחת, הגדר בשלוחת ניסוי נפרדת בימות המשיח:

```ini
type=api
api_link=https://YOUR-PROJECT.vercel.app/api/ivr
api_url_post=yes
api_wait_answer_music_on_hold=yes
```

4. בדוק שיחה עם מספר מזוהה: משחק מול בוט אחד, יצירת חדר עם שני טלפונים, המתנה לתור, הנחת קלף, בחירת צבע, ניתוק וחזרה, וביצוע הקשה חוזרת.
5. אם השלוחה אינה מחזירה תפריטים תקינים, בטל את השלוחה ובדוק את יומני Vercel. אין להעביר אותה לקו ציבורי לפני השלמת בדיקות.

### מגבלות ידועות
- אין עדיין אישור מבדיקת טלפון חיה; תהליך GitHub Actions הוסף, אך הצלחתו לא אומתה כאן.
- אין כרגע מנגנון בחירה חופשית של כל וריאציות חוקי טאקי; יש לאשר את החוקים לפני פרסום.
- זיהוי חזרה למשחק נעשה על ידי קוד חדר ומספר טלפון מזוהה.
- הבוטים משתמשים באלגוריתם מקומי ולא בשירות AI חיצוני.
- אין הגבלת זמן לתור ואין דילוג אוטומטי עקב חוסר פעילות.
